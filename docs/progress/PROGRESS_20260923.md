## 一、根因：数据在表里，执行端读不到

`EquipmentSkills._build()` 只把**固定列**映射进技能字典：

```gdscript
"cooldown": float(row[3]), "damage_mult": float(row[4]),
"reach": float(row[5]),   "duration": float(row[6]),
```

而执行端读的键**在整张表里出现次数为 0**（`grep` 实测）：

| 执行端读取 | 位置 | 表中出现次数 |
|---|---|---|
| `heal_pct` / `shield_pct` | `_apply_heal_and_shield` | **0** |
| `radius` | `_cast_aoe` | **0** |
| `element` | `_cast_projectile` | **0** |
| `half_angle` | `_cast_cone` | **0** |
| `knockback` / `pierce_count` / `count` | 各 kind | **0** |

**连带的三个数据缺陷**（实测确认，非推断）：

1. **第 5 列（reach）是第 4 列（damage_mult）的逐条副本**——133/133 全等。
   `cone` 类把倍率当扇形半径用：裂空斩 `1.8` 米、裂地斩 `5.0` 米。
2. **文件里混着 133 个 `\r`**（每条技能一个，都在描述末尾）。
   Godot 的 `get_line()` 把 `\r` 当行终止符 → 任何按行读取的工具都只读到
   描述就断行，表现为「133 条全匹配、0 条解析成功」且**不报任何错**。
3. **2 对同名装备**（元素爆发戒指、战吼头盔）各有稀有版与传奇版，
   而 `_by_equip` 按装备名存**单条** → 后写覆盖前写，**2 个技能永远放不出来**
   （133 条只剩 131）。

## 二、数据层：按描述逐条派生（`tools/derive_skill_extra.gd`）

**设计原则：只从描述文本派生，描述没写的不编造。**

- 描述写「冻结周围 4 米」→ `radius = 4.0`
- 描述只写「对周围敌人」→ **不给 radius**（用执行端默认值）
- 描述写「继承 50% 法强」→ `ap_ratio = 0.5`
  （**原表把这几个值一刀切写成 0.4**，与描述不符）

**产出**：133 条全部带 `extra`，`kind` 同时按描述修正：

| kind | 修正前 | 修正后 | 说明 |
|---|---|---|---|
| `buff` | 30 | 41 | 位移类（传送/闪现）曾被误判进来 |
| `dash` | 12 | 15 | 传送/闪现归位 |
| `projectile` | 22 | 8 | **11 条反伤类被误标**——反伤是自身状态 |
| `aoe` | 50 | 49 | — |
| `cone` | 7 | 5 | 火焰吐息/裂空斩等归位 |

**校验器**（同脚本，`=== VERIFY ===` 段）：逐条断言「描述里的关键词
是否都有对应字段」——治疗→`heal_pct`、护盾→`shield_pct`、米数→`radius`、
元素词→`element`、反弹→`reflect_pct`、击飞→`knockup`。
**这是 133 条人工填写不出错的唯一保障**，当前 133/133 通过。

**元素值合法性**：`holy` / `shadow` **不是** `ElementDefs` 的元素
（只有火冰雷土风毒 6 种）。派生器一度产出这两个值，已改为不写
element——伤害照常结算，只是不带元素叠层。校验器现在断言元素值全在枚举内。

## 三、执行端：6 处补线

| 改动 | 说明 |
|---|---|
| `_cast_buff` 从 `pass` 改为按语义分派 | 有 `radius` 走范围伤害、有 `heal_pct` 走治疗、有增益键挂词条，**三者可同时生效**（圣光审判 = 伤害 + 治疗） |
| `_cast_aoe` 增加 `at_aim` 分支 | 目标区域型（地裂术/星辰坠落）圆心是**准心方向 range 米处**，不是脚下 |
| `_cast_cone` 射程兜底 | 用 `maxf(reach, 3.0)` 而非 `get("reach", 3.0)`——后者拿到 0.0，扇形退化成零射程 |
| `_cast_dash` 认 `extra.range` | 装备的冲锋距离写在 `range`，职业技能写在 `dash_dist` |
| `_cast_projectile` 补 `count` | 冰锥术「发射 3 枚」此前只出 1 枚；多发按扇形铺开 |
| `_deal_damage` 加 `sd` 参数 | 技能自身的 `element` / `armor_pierce` / `guaranteed_crit` / `knockup` 现在生效 |

**新增两条通用通道**（避免为每个数值造词条）：

- `BuffHolder.apply(..., override_dur, override_params)` —— 词条只声明
  **参数结构**，具体数值由施加方指定。「加速」移速 +25%、「时空加速」+30%、
  「疾风步」+60% 共用同一条 `eq_skill_buff`，不再造上百个近义词条。
- `DamageZone.on_tick` 回调 —— 持续区域（毒雾/烈焰风暴/风暴之眼）复用
  已有的 `DamageZone`（已解决协程悬挂 + 像素管线透明不渲染两个坑），
  只把伤害结算接回 `SkillSystem` 走完整管线。

## 四、职业技能的 6 处悬空字段

`grep` 全项目确认零消费，全部补齐：

| 字段 | 技能 | 修法 |
|---|---|---|
| `hp_drain_pct` + `atk_from_drain` | 战士3 血怒 | 新增 `drain` 实现类型，扣血逻辑内聚在 `BuffHolder.tick` |
| `heal_pct_max` | 猎人2 生存本能 | `_apply_heal_and_shield` 兼容三种治疗字段名 |
| `heal_lost_pct` | 武僧3 背水一战 | 复用已存在的 `_heal_lost_hp()`（此前零调用） |
| `knockup` | 战士2 肘击 | 并入 `_deal_damage` 的 push |
| `windup` | 猎人3 穿心箭 | **未做**（见待办） |
| `lifesteal`（special） | 战士4 浴血 | **未做**（见待办） |

**两个关键发现**：

- 玩家侧的 `total_damage_reduction()` 此前**只对敌人用过**（玩家打敌人时读
  敌人的减伤），玩家自己身上的减伤词条零消费 → 「大地守护」挂了 buff 却不减伤。
- `_reflect_damage` 只读装备常驻的 `reflect_pct`，不看 buff →
  技能的反伤完全没有出口。

两处都已接上。

## 七、本轮修掉的历史缺陷（非本轮引入）

1. **第 5 列是第 4 列的副本**（133/133）—— `cone` 类的扇形半径等于伤害倍率
2. **133 个 `\r` 混在技能描述末尾** —— 任何按行读取的工具都会静默截断
3. **同名两版装备后写覆盖前写** —— 2 个技能永远无法释放
4. **`holy` / `shadow` 不是合法元素** —— 曾作为 element 值产出
5. **玩家侧减伤词条零消费** —— 技能挂了 buff 却不减伤
6. **反伤只有装备通道，没有 buff 通道** —— 技能反伤完全无效
7. **`_by_equip` 存单条** —— 同名多版互相覆盖
