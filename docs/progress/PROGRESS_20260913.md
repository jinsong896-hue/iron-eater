# 《噬铁者》开发进度 · 2026-09-13

## 一、今日完成条目

### 0a. 修复特殊房断链 + 恢复工程可编译（本次核心）

**背景**：工作区存在一大坨未提交 WIP（特殊房系统 + 房间数据精简 + 编辑器导出），
处于半成品状态。实测发现它已把工程打断——**文档声称的"全绿"是假绿灯**。

- **🔴 根因 1：`game_root.gd` 整脚本解析失败**
  - `_build_spawn_markers()` 调用了从未定义的 `_spawn_special_prop()`
  - GDScript 解析失败 → 整个脚本不可用 → `game_root` 变量为 Nil →
    `dungeon_graph` / `current_room_node` / `take_damage` 全部连锁报错
  - **后果**：`test_room_flow` / `floor_flow` / `death_flow` / `combat_system`
    / `door_physics` **五套场景测试全红**
  - 修复：新增 `_spawn_special_prop()`，在 `_build_spawn_markers` 的主流中
    按 `shop_npc` / `heal_shrine` / `event_shrine` 三类生成交互物实体
- **新增 `world/props/special_prop.gd`**（脚本构建占位视觉，对齐 chest.gd 模式）：
  - 商店 NPC：方柱躯干 + 头部 + 柜台，暖黄配色
  - 治疗泉水：圆柱基座 + 悬浮水球，青蓝发光
  - 事件祭坛：四面尖碑 + 悬浮核心，紫红发光
  - 各配 OmniLight 强化可交互提示
- **🔴 根因 2：特殊房从未接入地牢生成（"无入口"）**
  - `DungeonGenerator._assign_room_types()` 只分配 `start` / `normal` / `elite` / `boss`
  - **完全没有** shop / heal / event 分配 → 特殊房永远不会出现在地牢里，
    整套 `SpecialRoomService` + `interact_special()` 全部是死代码
- **特殊房接入生成器**：新增 `_assign_special_rooms()`，按房间总数配额分配
  （`clampi(size/4, 1, 3)`，最多 shop/heal/event 各一间，只挑 normal 房改造）
- **🔴 根因 3：特殊房 JSON 无门 → 进去出不来**
  - `room_shop/heal/event.json` 的 `doors` 为空数组，且 `floor` / `walls` 也为空
  - 特殊房 `activate()` 走 `_lock_doors()` 分支，但房间里根本没有门 →
    交互完成后也无门可开 → **设计上就是死锁**
  - 修复：三个 JSON 补齐全套数据（南墙中心开口 + 门、环形围墙 51 段、地板 140 格）
- **`room_templates` 注册补全**：`_register_templates()` 初始化字典补上
  `shop` / `heal` / `event` 三个 key（此前靠动态兜底，行为不确定）

### 0a-2. 门禁抓出的第二批问题（提交 76bcc96b 之后）

**背景**：首轮提交后重跑门禁，`room_flow` **随机失败**——这恰好证明门禁有效。
深挖发现两个只有特定随机种子才暴露的真问题：

- **🔴 软锁：商店房金币不足时房间永久停滞**
  - `interact_special()` 失败时（商店金币不足 / 泉水已满血 / 消耗品背包满），
    返回 `ok=false`，但**门已经锁上了**，`is_cleared` 保持 false
  - 且 `activate()` 回访该房仍会再次 `_lock_doors()` → **玩家被永久关在房里**
  - 修复：已结算房间（`_special_used`）回访时只解锁不重发奖励；
    `interact_special()` 对已结算房间返回 `already_used` 并解锁
  - 说明：更彻底的解法（交互前不锁门）需重做特殊房 UI 流程，已登记待办
- **🟠 刷怪概率不走种子**：`_spawn_enemies()` 里 70% 判定用全局 `randf()`，
  不读房间种子 → 同一层每次结果不同、测试无法复现
  - 修复：改用房间种子 `rng.randf()`
- **🟠 测试只覆盖了随机一种特殊房**：原测试取 `break` 后第一个特殊房，
  商店/泉水路径**从未被执行过**（正是它们藏着软锁）
  - 修复：遍历本层实际分配到的**全部**特殊房类型，并分别覆盖
    "有怪 / 空房"两条刷怪路径（空房是正常的，原测试却断言必有怪）
