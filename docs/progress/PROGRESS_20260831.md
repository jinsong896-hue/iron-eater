### 0m. 修复穿门不传送根因 + 右上角小地图实装

- **穿门不传送的真根因**（此前两轮修复都没打中）：

    **静态空函数** `_on_door_trigger`（pass），而 door_trigger.gd 的

    因方法同名自动连接
  - 结果：真实物理穿门时信号发给空函数，什么都不发生；旧测试之所以
    「通过」是因为直接调用 `trig._on_body_entered(...)` 模拟——掩盖了
    信号链断裂
  - 修复：连接改为 `child.body_entered.connect(child._on_body_entered)`，
    删除死代码静态空函数
  - 新增 `test_door_physics.tscn`（6 项）：**真实物理信号链**验证——
    玩家瞬移到门区、跑 30 物理帧、断言房间切换发生（不再模拟调用）

### 0f. 修复完整地牢房间流程（两处断链）

- **问题 1——门收集失效**：RoomController 找门用的是「房间根直接子节点」，
  但门实际建在 `Room_N/Doors/` 容器下（`Door_*` 命名）→ 控制器永远收集 0 个门，
  锁门/开门对所有房间无效。修正为从 Doors 容器收集。
- **问题 2——门方向为空**：DoorBuilder 从未给 DoorTrigger 写 `direction`，
  玩家穿门时 `door_opened` 信号发空字符串 → GameRoot 按方向找邻接房间永远失败，
  **穿门不切房**。修正：建门时写入方向。
- **问题 3——切房后玩家落点**：普通房 JSON 无 player_spawn 标记，玩家切房后
  fallback 到硬编码 (15,0,15) 可能卡墙。修正：`_place_player(enter_direction)`
  按进入方向放在入口门内侧 1.5m（北门进→南侧内侧）；无门房间居中。
- 顺手发现（未修，数据小瑕疵）：room_start.json 有两条 east 门数据（重复 id），
  生成时第三个门节点带 @ 后缀；不影响流程。
