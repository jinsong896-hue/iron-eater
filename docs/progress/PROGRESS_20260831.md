### 1. P0：修复 HD-2D 重构后的工程不可启动问题

- 背景：HD-2D 大重构（目录五层化 + 装备数据层重建 e53cd0c3）之后，工程无法启动——
  `GameManager` autoload 编译失败，测试套件大量 SCRIPT ERROR。
- 完成情况：
  - **诊断出真正根因**：`.godot/global_script_class_cache.cfg`（gitignore 的编辑器生成文件）
    不存在，导致 `--script`/`--headless` 模式下所有 `class_name` 解析失败。
    上次会话误诊为循环依赖，开始移除 class_name（改到一半），反而制造了新的悬空引用。
  - **恢复 class_name 一致性**（推翻半成品改动方向，保留其中有价值的修复）：
    - `equipment_template.gd` / `equipment_instance.gd`：恢复 `class_name`，
      保留 `from_dict` 改为实例方法的正确修复（原版把它当静态工厂用是 bug）
    - `equipment_manager.gd`：修复两处 `affix.percent` 悬空字段（AffixData 实际字段是
      `operation` 枚举），按 FLAT/PERCENT 正确分流 Modifier
  - **从 git 历史恢复两个误删文件**（目录精简 b2a0d9bb 时被删但仍有引用）：
    - `gameplay/combat/combat_core.gd`（原 `runtime/combat/`）：`balance_calc.gd` 与
      `test_iron_studio.gd` 引用，战斗计算核心
    - `data/balance/game_balance.gd`（原 `old_data/balance/`）：`player.gd` 与
      `skill_system.gd` 引用，数值平衡配置
  - **修复悬空类型引用**：
    - `loot_system.gd`：`EnemyData` 类型不存在 → 参数改为兼容 MonsterData/Dictionary；
      `EquipmentDefs.rarity_color()` 不存在 → 改用 `RARITY_COLORS` 字典；动态掉落脚本
      改为缓存静态脚本（避免每次掉落重新编译 + 动态脚本内 class_name 解析问题）
    - `enemy_spawner.gd`：`spawn_boss` 的 `EnemyData` 参数同样改为 duck-typing
  - **修正过时测试断言**：FusionRules 上限实为 25 次（策划口径：25 次后红双手剑
    560→1120），旧断言按上限 5 写；改为断言 25 满级 +100%、24 可融、25 不可融
  - **修复测试框架假绿灯**：脚本 `load()` 失败（编译错误返回 null）此前被静默跳过，
    测试仍报 PASSED；新增 `_require_script()` 将加载失败计入失败并提前返回，
    退出码改为明确的 0/1
  - **文档同步**：README.md 重写为 HD-2D 重构后真实状态（旧 2D 路径/能力描述全部
    清除，白装如实标注 7 件最小版）；CLAUDE.md 目录树与实际对齐，新增「类缓存陷阱」
    与「headless dummy 渲染器噪音」两条注意事项。
