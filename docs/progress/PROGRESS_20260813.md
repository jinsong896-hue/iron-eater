  - 说明：无头模式无法路由合成鼠标事件（引擎限制），左键验证采用“遮罩移除 + 按钮可见可点 + 点击处理器触发跳转”组合断言；真实窗口内 Godot 标准输入路由会把左键点击送达最上层可见控件（即按钮）

### 6. 修复“开始游戏后闪退”（用户反馈：无法进入初始房间）

- 完成情况：
  - 现象：点击“开始游戏”后进程直接闪退，日志报 `Parameter "data.tree" is null`（`scene_transition.gd:29` 的 `get_tree()` 为空）
  - 根因：`SceneTransition` 是主菜单场景的子节点；`change_scene_to_file` 切换场景时会连同旧场景一起释放过渡节点，淡出协程恢复后 `get_tree()` 已为空 → 脚本错误后进程退出
  - 修复：新增全局单例 `SceneTransitionManager`（autoload，`scripts/core/scene_transition_autoload.gd`）跨场景存活；主菜单控制器与暂停菜单改用该单例，不再各自创建过渡节点
  - 新增回归测试 `tests/test_enter_dungeon_flow.gd/.tscn`：完整走“创建存档 → 新游戏配置 → 开始游戏 → 场景切换”，由测试监视器（`--flow-test` 时激活）跨场景断言地牢进入成功
- 验证证据：
  - `test_enter_dungeon_flow`（带 `-- --flow-test`）：全部断言通过——切换后当前场景为地牢主场景、地牢管理器存在、玩家已进入初始房间、初始房间已生成（12 个房间）、玩家位置在初始房间内（房间可用区中心）

| 现象 | 原因 | 解决方案/状态 |
|---|---|---|
| `GameCatalog.get_class` 解析失败 | 与 Object 内置 `get_class()` 重名 | 改名 `class_info/difficulty_info/mode_info`，已解决 |
| 设置应用时音频总线索引越界 | 工程默认只有 Master 总线 | 增加总线存在性判断，已解决 |
| 存档损坏回退测试失败 | .bak 保存的是上一版好档（预期行为），断言写错 | 修正断言为“回退到有效版本”，已解决 |
| 第一层 2×2 房间补建越界 | `_ensure_min_rooms` 未检查母网格边界 | 增加 [-half, half] 边界过滤，已解决 |
| 导航网格边合并警告（4~6 处） | 手工导航多边形门洞处边过密 | 不影响寻路，列入 P2 打磨 |
| 集成测试首次运行无输出挂起 | 场景脚本误用 SceneTree 的 `root` | 改为 `get_tree().root`，已解决 |
| 主菜单面板不可见、无法交互 | `_menu_panel()` 用默认节点名注册，`_show_state` 找不到面板 | 显式命名注册；新增交互测试，已解决 |
| 空存档卡无法创建 | 空槽的“进入”按钮被隐藏 | 空槽显示“＋ 创建存档”，已解决 |
| 后台批量无头测试原生访问冲突（0x58） | 多个 Godot 实例同项目并发/沙箱无 user:// | 清理残留进程；后续测试逐条运行并落盘日志；已复验全部通过 |
| test_dungeon 偶发失败（事件/隐藏房数量） | 分配器 `shuffle` 依赖全局随机数，结果不确定 | 移除 shuffle，分配确定性化，已解决 |
