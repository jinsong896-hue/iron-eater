# 技能机制完善计划

> 日期：2026-09-23
> 范围：**职业形态技能（40 条）** + **装备主动技能（133 条）** 的机制补全。
> 不在范围：新增技能、数值平衡、音效（只留接口）。

---

## 〇、范围：两条技能线

项目里有**两套独立的技能数据源**，共用同一个执行器 `SkillSystem`：

| | 职业技能 | **装备主动技能** |
|---|---|---|
| 数据源 | `data/classes/class_defs.gd` | `data/equipment/equipment_skills.gd` |
| 条数 | 40（5 职业 × 5 形态 × 2） | **133** |
| 索引方式 | `class_id` + `form_slot` | 装备显示名 |
| 获得方式 | 选人时按形态固定 | 装上带技能的装备即入池 |
| 上槽 | 是 | 是（占用同样的 6 个技能槽） |
| 本计划占比 | 阶段 C（6 处补线） | **阶段 A + B（主体）** |

**装备技能是本计划的主体**——它的机制缺失最严重：

- **30 条 `buff` 类全部空放**（`_cast_buff` 是 `pass`，而装备技能没有 `self_buffs` 字段）
- **122/133 条**的数值进不了技能字典（表结构缺列，见 1.2）
- **11 条反伤类**被误标成 `projectile`，**50 条 `aoe`** 里目标区域型打错位置

职业技能相对健康——数据完整，只有 6 个字段悬空（见 1.3）。

## 一、问题分析：现状核查

### 1.1 已跑通的部分（不必动）

| 项 | 状态 |
|---|---|
| `SkillSystem` 的 12 种 kind 分派 | ✅ 全部有实现（`skill_system.gd:86-98`） |
| 冷却 / 资源消耗 / 生命消耗 | ✅ `cast_skill` 统一处理 |
| 伤害结算口径 | ✅ 与普攻共用 `DamagePipeline`，含护甲穿透 / 暴击 / 背刺 |
| 形态印记叠层 | ✅ `_stack_form_marks_on` 只叠给真正挨打的敌人 |
| 技能槽数据层 | ✅ `SkillLoadout`（6 槽 + 被动池）已实现 |
| 技能管理 UI | ✅ `ui/skills/skill_panel.gd` 已存在（从背包页切页打开） |
| 装备技能池 | ✅ `EquipmentSkills.available_for()` 按已装备过滤 |

**结论**：骨架完整，缺的是**数据 → 执行的最后一跳**。

### 1.2 根因：装备技能表的数值进不了技能字典

`EquipmentSkills._build()`（`equipment_skills.gd:166-196`）只把**固定列**映射成字典：

```gdscript
"cooldown": float(row[3]),
"damage_mult": float(row[4]),
"reach": float(row[5]),
"duration": float(row[6]),
```

第 9 列 `extra` 只有召唤/隐身两类填了内容，**其余 122/133 条是 `{}`**。

而执行端读的键**全部不存在**：

| 执行端读取 | 出现位置 | 装备技能表中出现次数 |
|---|---|---|
| `heal_pct` / `shield_pct` | `skill_system.gd:528-529` | **0** |
| `radius` | `_cast_aoe` / `_cast_spread` | **0** |
| `half_angle` | `_cast_cone` | **0** |
| `element` | `_cast_projectile` | **0** |
| `knockback` | 全部 kind | **0** |
| `pierce_count` | `_cast_projectile` | **0** |
| `range` / `hit_count` | `_cast_teleport` / `_cast_multi_hit` | **0** |
| `speed` | `_cast_projectile` | **0** |
| `self_buffs` / `target_buffs` | `_apply_self_buffs` / `_apply_target_buffs` | **0** |

**后果举例**（全部已核实）：

| 技能 | 表里数据 | 实际执行 | 玩家感受 |
|---|---|---|---|
| 护盾术 | `["护盾术","护盾术","buff",22,0,0,8,...]` | `_cast_buff` → `pass`；`shield_pct` 缺失 → 直接 return | **按了没反应** |
| 圣光审判 | `buff, 20.0, 1.5, 1.50, 0.0` | `_cast_buff` → `pass` | 伤害和治疗**都没了** |
| 冰封领域 | `buff, 20.0, 1.2, 1.20` | `_cast_buff` → `pass` | 冻结和伤害**都没了** |
| 裂地巨斧 | `cone, 20.0, 5.0, 5.00` | `_cast_cone` 读 `reach`=5.0 ✅、`half_angle` 默认 60° | **只有这一条勉强能用** |
| 穿透长弓 | `projectile, 18.0, 3.5, 3.50` | `_cast_projectile` 读 `speed` 默认 12、`element` 默认空 | 能出弹，但**无元素、穿透次数丢失** |
| 冰锥术法杖 | 描述「发射 **3 枚**冰锥」 | `_cast_projectile` 只出 **1 枚** | 数量不符 |

**核心问题**：表把「伤害倍率」「射程」「持续」塞进固定列，但**元素、半径、数量、治疗、护盾、buff、击退**这些维度根本没有列——描述里写了，数据结构里没地方放。

### 1.3 职业技能的 8 处字段悬空

职业技能数据本身完整，但有 8 个字段**全项目零消费**（`grep` 核实）：

| 字段 | 所属技能 | 策划描述 | 现状 |
|---|---|---|---|
| `hp_drain_pct` + `atk_from_drain` | 战士3 血怒 | 每秒失去 1% 最大生命换等量攻击力 | **完全没实现** |
| `knockup` | 战士2 肘击 | 击飞；撞到其他敌人双方再受一次伤害 | `_cast_cone` 不读；`buff_defs` 有 `knockup` 但技能没施加 |
| `windup` | 猎人3 穿心箭 | 蓄力 0.8 秒 | `_cast_projectile` 不读，**立即发射** |
| `heal_pct_max` | 猎人2 生存本能 | 立即恢复 20% 最大生命 | 执行端读的是 `heal_pct`（名字不同）→ **没回血** |
| `heal_lost_pct` | 武僧3 背水一战 | 开启瞬间恢复 20% 已损生命 | **没回血** |
| `lifesteal`（special） | 战士4 浴血 | 吸血 50% | `player.gd` 读的是装备键 `life_steal`，**形态的 0.50 没接上** |
| `mana_regen_up`（special） | — | 魔力回复加成 | ✅ 已由 `skill_facade.gd:146` 消费 |

**`knockup` 已有现成通路**：`data/buffs/buff_defs.gd:51` 定义了 `["knockup", "击飞", Kind.DISPLACE, ...]`，只需技能施加它。

### 1.4 三个 kind 名不副实

装备技能表里 kind 是**按关键词猜的**，与描述不符：

| kind | 条数 | 实际语义 | 问题 |
|---|---|---|---|
| `projectile` | 22 | **11 条真投射物** + **11 条反伤/格挡类**（「3秒内反弹100%伤害」） | 反伤是**自身状态**，不是投射物 |
| `aoe` | 50 | 混杂了：目标区域型（地裂术）、自身光环型（战吼）、位移型（无畏冲锋）、自增益型（石肤） | 用「以自身为圆心」结算，**目标区域型全打错位置** |
| `buff` | 30 | 混杂了：纯自增益（加速）、纯护盾（护盾术）、伤害+治疗（圣光审判）、控制+伤害（冰封领域） | `_cast_buff` 是 `pass`，**全部空放** |

**`_cast_buff` 是 `pass`**（`skill_system.gd:294-295`）本身没错——职业技能的 buff 全靠 `self_buffs` 字段。但**装备技能一条 `self_buffs` 都没有**，于是 30 条 buff 技能全部空放。

## 二、机制清单与缺口

### 2.1 装备技能表需要新增的字段（按描述归纳）

对 133 条描述逐条归纳，需要的字段共 **13 个**：

| 字段 | 语义 | 覆盖条数 | 执行端 |
|---|---|---|---|
| `radius` | 效果半径（米） | ~45 | `_cast_aoe` / `_cast_spread` |
| `element` | 元素（fire/frost/static/earth/wind/poison/holy/shadow） | **36** | `_cast_projectile` / `_deal_damage` |
| `heal_pct` | 回复最大生命 % | **19** | `_apply_heal_and_shield` |
| `shield_pct` | 护盾（最大生命 %） | **8** | `_apply_heal_and_shield` |
| `self_buffs` | 自身增益词条 | ~20 | `_apply_self_buffs` |
| `target_buffs` | 目标减益词条 | ~25 | `_apply_target_buffs` |
| `knockback` / `knockup` | 击退 / 击飞 | ~10 | 新增 |
| `pierce_count` | 穿透敌人数 | ~6 | `_cast_projectile` |
| `count` | 弹数 / 召唤数 | ~5 | `_cast_projectile` / `_cast_summon` |
| `range` | 施法距离 | ~20 | `_cast_teleport` / 目标区域型 |
| `speed` | 投射物速度 | ~20 | `_cast_projectile` |
| `thorns_pct` | 反弹伤害 % | **11** | **新增通道** |
| `block_all` | 期间格挡所有伤害 | **5** | **新增通道** |
| `tick_interval` | 持续型结算间隔 | **42** | **新增通道（SkillZone）** |

> 上表「覆盖条数」为 `grep` 描述文本的实测值，非估计。

### 2.2 需要新增的执行机制（4 个）

| 机制 | 说明 | 落点 |
|---|---|---|
| **目标区域型施法** | 「在目标区域召唤地刺」——伤害中心不是自身，是准心方向 N 米处 | `_cast_aoe` 增加 `at_aim` 分支 |
| **持续型施法** | 「持续 2 秒，每 0.5 秒造成伤害」——目前只结算一次 | 新增 `SkillZone` 节点（挂在世界，按 tick 结算） |
| **反伤 / 格挡状态** | 「3 秒内反弹 100% 伤害」——需要一个限时状态 | **复用已有通道**：`reflect_pct`（`player.gd:1880`）与 `buff_defs.gd:84` 的 `{"reflect": 0.20}` 先例。只需补 `block_all` |
| **蓄力（windup）** | 「蓄力 0.8 秒」——延迟结算 + 期间可被打断 | 新增延迟计时，或在 `SkillZone` 上挂 windup |

### 2.3 职业技能的 6 处补线

| 技能 | 要补的 |
|---|---|
| 血怒 | `hp_drain_pct` 每秒扣血 → 换算成 `atk` 加成（`atk_from_drain`） |
| 肘击 | `knockup` → 施加 `buff_defs` 的 `knockup`；被击飞者撞人二次伤害 |
| 穿心箭 | `windup` → 延迟 0.8 秒发射；穿透 ≥2 敌时冷却 -2 秒 |
| 生存本能 | `heal_pct_max` → 改名或加别名，让 `_apply_heal_and_shield` 读到 |
| 背水一战 | `heal_lost_pct` → 复用已有的 `_heal_lost_hp()`（该函数已存在，只是没人调） |
| 浴血 | 形态 `lifesteal` 0.50 接入 `player.gd` 的吸血链路 |

## 三、执行计划

### 阶段 A：装备技能表重建（数据层）

**A1. 扩展表结构**——`EquipmentSkills.TABLE` 每行第 9 列 `extra` 从「少数几条有」变成「逐条补齐」。
133 条逐条按描述填写，不猜、不套模板。

**A2. `_build()` 补齐固定列 → 标准键的映射**——目前第 5/6 列被映射成 `reach`/`duration`，但语义随 kind 变化（`buff` 类的第 6 列是持续秒数，`aoe` 类的第 5 列是半径）。改为按 kind 解释，或直接全部搬进 `extra` 显式声明。

**A3. 校验脚本**——写一个 `tools/verify_skills.gd`，对每条技能断言「描述里出现的关键词 ↔ 数据里有对应字段」：
- 描述含「治疗」→ 必须有 `heal_pct`
- 描述含「护盾」→ 必须有 `shield_pct`
- 描述含「N 米」→ 必须有 `radius` 或 `range`
- 描述含「冰霜/火焰/毒素/雷电/土/风」→ 必须有 `element`
- 描述含「反弹」→ 必须有 `thorns_pct`
- 描述含「击飞」→ 必须有 `knockup`

**这是本阶段的核心产出**——没有它，A1 的 133 条人工填写无法验证。

### 阶段 B：执行端补线（逻辑层）

**B1.** `_cast_buff` 从 `pass` 改为「按 kind 语义分派」：有 `radius` 的走范围伤害，有 `heal_pct`/`shield_pct` 的走治疗护盾，有 `self_buffs` 的挂词条。三个可以同时生效（圣光审判 = 伤害 + 治疗）。

**B2.** `_cast_aoe` 增加 `at_aim` 分支：`sd.has("at_aim")` 时以「施法者 + 朝向 × range」为圆心。

**B3.** 新增 `SkillZone`（`gameplay/skills/skill_zone.gd`）：持续型效果（毒雾、燃烧地面、箭雨、风暴之眼、旋风斩）。字段 `tick_interval` / `duration` / `radius` / `damage_mult` / `element`。

**B4.** 反伤/格挡通道：`reflect_pct` **已有**（`player.gd:1880` 读装备键，`buff_defs.gd:84` 已有 `{"reflect": 0.20}` 的 buff 先例）。只需给这 11 条技能挂上带 `reflect` 参数的限时 buff，并新增 `block_all` 词条（5 条）。

**B5.** `_cast_projectile` 补 `count`（多发）与 `pierce_count`。

**B6.** `_deal_damage` 增加 `sd` 参数（当前是 `null`，导致技能自身的 `element` 用不上，`skill_system.gd:484-492` 已注明这个缺陷）。改动面：全部调用点，共 12 处。

### 阶段 C：职业技能补线

**C1.** 血怒：`hp_drain_pct` + `atk_from_drain`（新增 buff 词条或 skill 专属结算）。
**C2.** 肘击：`knockup` → 施加 `buff_defs` 的 `knockup`；撞人二次伤害。
**C3.** 穿心箭：`windup` 延迟发射。
**C4.** `heal_pct_max` / `heal_lost_pct` 统一到 `_apply_heal_and_shield`（`heal_lost_pct` 直接调已有的 `_heal_lost_hp`）。
**C5.** 形态 `lifesteal` 接入 `player.gd` 吸血链路。

### 阶段 D：验证

**D1.** `tools/verify_skills.gd` 全绿（阶段 A3 的产出）。
**D2.** 新增 `tests/test_skill_mechanics.gd`：对每条 kind 至少一个代表技能，断言「施法后世界状态发生预期变化」（敌人掉血 / 自己回血 / 获得 buff / 生成投射物）。
**D3.** `bash tests/run_all.sh` 全量门禁。

## 四、风险与边界

| 风险 | 说明 | 应对 |
|---|---|---|
| **133 条人工填写出错** | 描述与字段的对应靠人读 | A3 校验脚本 + D2 逐 kind 测试 |
| **`_deal_damage` 加参数** | 12 处调用点全改 | 用默认参数 `sd: Dictionary = {}`，老调用点不动 |
| **`SkillZone` 与换房冲突** | 切房时残留 | 挂到房间节点下（与投射物同一策略，见 `_projectile_parent`） |
| **反伤通道与装备 `reflect` 重复** | 装备已有 `reflect` → `reflect_pct`（SPECIAL_STAT 104） | **本就同一通道**，直接复用：技能挂带 `reflect` 参数的限时 buff，不新开 key |
| **数值** | 描述里的「100% 反弹」「300% 攻击力」是否合理 | **本阶段不做平衡**，按描述原值落地 |

**明确不做**：
- 数值平衡（按描述原值）
- 音效（只留接口）
- 新增技能
- 技能图标 / 特效美术

## 五、需要用户确认的事项

1. **`knockup` 撞人二次伤害**（肘击描述）——实现成本较高（需要击飞物体与其他敌人的碰撞检测）。是否降级为「只击飞，不撞伤」？
2. **`_cast_buff` 的伤害口径**——圣光审判等「造成 150% 法强伤害」，目前技能伤害统一按**面板 ATK** 结算（`_panel_atk`）。法强（AP）技能是否需要单独走 AP 口径？这会影响约 30 条技能。
3. **持续型技能（阶段 B3）** 是否本轮做？涉及新节点类型，改动面最大。
4. **蓄力（`windup`）** 是否本轮做？只影响 1 条技能（穿心箭）。
5. **技能管理页**：用户此前反馈「会有角色还没有的其他角色的技能」——`available_pool` 是否应只返回**当前职业形态**的技能 + **已装备**提供的技能？需确认口径。

# 例：确认装备技能表无 radius 字段
grep -c '"radius":' data/equipment/equipment_skills.gd          # → 0
