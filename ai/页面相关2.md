## 一、整个菜单建议做成这套结构

```text
启动游戏
   ↓
【主菜单】
   ├─ 开始游戏

   │  【存档选择】
   │      ├─ 存档 01
   │      ├─ 存档 02
   │      ├─ 存档 03
   │      └─ 空存档 → 添加存档
   │
   │      点击已有存档
   │          ↓
   │     【存档主页】
   │          ├─ 开始游戏
   │          │     ↓
   │          │  有未结束游戏？
   │          │    ├─ 是 → 是否结束上一局？
   │          │    └─ 否
   │          │
   │          │     ↓
   │          │ 【新游戏配置】
   │          │     ├─ 选择角色
   │          │     ├─ 选择模式
   │          │     ├─ 选择难度
   │          │     └─ 开始
   │          │
   │          ├─ 继续游戏
   │          ├─ 升级
   │          └─ 退出当前存档
   │
   ├─ 设置
   └─ 退出游戏

游戏中
   ↓ ESC

   ├─ 继续游戏
```

这套结构最大的优点是：**主菜单管理“玩家档案”，存档主页管理“这个玩家档案里的游戏内容”，游戏内暂停菜单只处理当前这一局。** 不容易乱。

# 二、第一页：游戏主菜单

建议画面比例大概这样：

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                                                              │
│               《噬 铁 者》                                   │
│                                                              │
│        大面积动态美术 / 世界观场景                            │
│                                                              │
│          主角 / 地牢 / 巨型机械遗迹             开始游戏     │
│                                                 设置         │
│                                                 退出游戏     │
│                                                              │
│                                                              │
│                                               V0.1.0         │
└──────────────────────────────────────────────────────────────┘
           左侧约 70%                         右侧约 30%
```

### 美术画面

不要让 UI 抢画面。

你的游戏本身定位是“暗黑哥特 + 克苏鲁元素，而且随着地牢深入逐渐诡异化”。fileciteturn0file0L75-L78

所以开始页面可以直接建立一个非常强的第一印象：

**左下：** 主角背影。

**中央：** 巨大的地牢入口、废弃熔炉或者机械遗迹。

**远处：** 隐约出现不可名状的巨大轮廓。

**环境：** 铁锈、锁链、废弃机械、蒸汽、灰尘颗粒。

画面可以有很轻微的动态：

火星飘落、雾气移动、锁链晃动、远处火光闪烁。

但一定不要做得特别吵。

因为这里的目标不是炫 UI，而是：

> **第一次打开游戏，玩家就知道这是一个阴暗、危险、关于“铁”和“吞噬”的世界。**

# 三、右侧菜单不要做成按钮框

这一点我比较建议你坚持。

不要：

```text
┌───────────┐
│ 开始游戏  │
└───────────┘
```

而是直接使用文字：

```text
开始游戏

设置

退出游戏
```

鼠标悬停或者键盘选中后：

```text
> 开始游戏
```

或者：

```text
开始游戏  ━━━━━
```

再配一个非常轻微的金属摩擦音。

这样比一排黑色矩形框更符合《噬铁者》的气质。

# 五、已有存档应该显示什么

不要显示太多。

一个存档建议只展示：

| 内容 | 示例 |
|---|---|
| 存档编号 | 存档 01 |
| 当前代表角色 | 战士 · 狂怒之刃 |
| 总游戏时间 | 12h 43m |
| 最高地牢层数 | 第 6 层 |
| 剧情进度 | 第 2 章 |
| 最后游戏时间 | 2026/08/12 |
| 是否存在进行中的一局 | 地牢探索中 |

最后一项很重要。

例如：

```text
存档 01

战士 · 狂怒之刃
游戏时间：12h 43m
最高抵达：第 6 层

● 存在未完成的探索
```

这样玩家还没进入存档，就已经知道里面有没有可以“继续游戏”的内容。

# 八、「继续游戏」的状态非常重要

按照你的要求：

### 有进行中的游戏

显示：


可以正常点击。

下面附一行小字：


### 没有进行中的游戏

```text

```

但文字变灰。


灰掉比隐藏好。

因为隐藏以后，玩家会不知道这个游戏到底有没有“继续游戏”功能。

# 十四、ESC规则建议统一

你提出“ESC返回上一级”是很好的，但必须从一开始就统一。

建议最终规则只有这一套：

- **主菜单：** ESC 无效果，或者弹“是否退出游戏”；我更建议无效果。
- **存档选择：** ESC → 主菜单。
- **存档主页：** ESC → 存档选择。
- **新游戏配置：** ESC → 存档主页。
- **升级：** ESC → 存档主页。
- **设置：** ESC → 打开设置前的页面。
- **游戏中：** ESC → 暂停游戏。
- **暂停状态再次 ESC：** 关闭暂停菜单，继续游戏。

这样玩家永远不用学习新的操作规则。

# 十五、游戏内暂停菜单

游戏内按 ESC：

首先：

```text
get_tree().paused = true
```

游戏完全停止。

然后中央或者右侧弹：

```text
                暂停

              继续游戏

                设置

              退出游戏
```

这里我建议把你说的“退出游戏”再拆清楚一点。

直接写“退出游戏”容易让玩家理解成关闭 EXE。

最好点击后再弹：

```text
退出当前游戏？

[返回主菜单]
[退出至桌面]
[取消]
```

其中：

### 返回主菜单

保存当前可以保存的数据，然后回到当前存档主页或者主菜单。

### 退出至桌面

关闭游戏。

这两个最好不要混在一起。

# 十七、三个存档的数据结构也可以现在直接定下来

```text

├─ create_time

├─ total_play_time

├─ progression
│   ├─ story_progress
```

> 战士 · 第4层地下沼泽  
> 31:42 前自动保存

这样玩家第一次看到主菜单，就知道自己上次玩到哪里了。

如果手柄按特定快捷键，例如 `Y`，可以直接进入最近存档，但不要把“继续游戏”变成第四个大按钮，否则会与存档系统产生逻辑重复。

---

### 2. 存档页面增加“状态识别”，而不仅仅显示数据

目前建议的存档卡已经有角色、游戏时间、最高层数等信息，还可以进一步做成不同视觉状态。

| 状态 | UI表现 |
|---|---|
| 正常存档 | 正常白/暗金 |
| 存在未完成探索 | 微弱脉冲圆点 +“探索进行中” |
| 空存档 | 极简“＋ 创建” |
| 备份恢复 | 黄色提示“已从备份恢复” |
| 存档损坏 | 暗红“存档异常” |
| 旧版本存档 | “正在迁移存档版本” |

你的代码已经有 `.bak`、`.tmp` 和 `save_version`，所以 UI 最好也把这些底层能力反馈给玩家，而不是悄悄处理。

特别是：

> “检测到存档异常，已成功从备份恢复。”

这种信息最好使用右下角 Toast，而不是弹窗打断玩家。

---

### 3. 增加统一的 Toast 通知系统

这是目前非常值得补的一层。

例如：

> 游戏已保存  
> 设置已应用  
> 已解锁「战士·进阶Ⅰ」  
> 存档已恢复  
> 无法创建存档  
> 手柄已连接

统一从右下角淡入：

```text
                      ┌────────────────────┐
                      │ ✓ 游戏已自动保存   │
                      └────────────────────┘
```

2～3 秒消失。

以后大量系统都会需要这个功能，因此建议直接做：

```text
NotificationManager
```

而不是每个页面自己做提示。

---

### 4. 新游戏页面增加“最终配置摘要”

现在是：

职业 → 形态 → 模式 → 难度 → 开始。

我建议右下角再增加一个非常简洁的最终摘要：

```text
本次探索

战士 · 狂怒之刃
地牢模式
普通难度

随机种子：78421933

预计时长
60～90 分钟

────────────
开始探索
```

尤其你的地牢模式策划本身就是约 1～1.5 小时单局。fileciteturn0file0L108-L118

这样玩家点击“开始”以前非常清楚自己选了什么。

---

### 5. 难度不要只显示“简单 / 普通 / 困难”

应该告诉玩家**究竟改变什么**。

例如选中困难：

```text
困难

敌人生命        +25%
敌人伤害        +20%
精英出现率      +15%
资源压力        提高

适合已经熟悉吞噬与融合系统的玩家。
```

否则很多游戏里的“困难”只是一个没有信息的词。

后面如果修改平衡，只需要从 Difficulty Resource 读取这些说明。

---

### 6. 给职业选择加入“操作难度”和玩法标签

你的五个职业操作逻辑区别其实已经很明显，比如战士偏近战重装，猎人偏走A，法师远程技能等。fileciteturn0file0L897-L955

所以角色页面可以出现：

```text
战士 · 狂怒之刃

近战 / 生存 / 爆发

操作难度
●●○○○

核心资源
怒气

推荐
初次游玩
```

法师可能：

```text
操作难度
●●●○○
```

判官：

```text
●●●●○
```

这对第一次玩的玩家非常重要。

---

### 7. 加一个“推荐角色”标识

第一局不要让玩家面对五个职业完全不知道怎么选。

例如：

> ★ 推荐首次使用

放在战士旁边。

但不要限制。

这是轻度引导，不是强制教程。

---

### 8. Locked 内容不要只是“灰”

比如：

```text
终极形态
```

灰掉以后，鼠标移过去应该展开：

> 尚未解锁  
> 通关隐藏第9层「混沌裂隙」后解锁

这样锁定内容本身就变成玩家长期目标。

这与你现在的 3 / 6 / 8 / 9 层形态解锁结构非常适合。fileciteturn2file0L189-L198

---

### 9. “升级”页以后不要传统技能树铺满整个屏幕

我反而建议做成一种更符合《噬铁者》的**机械核心/血肉铁器**形式。

中央一个：

> 噬铁核心

周围向外生长不同路线：

```text
                生存
                  ○
                 ╱
        经济 ○──●──○ 战斗
                 ╲
                  ○
                探索
```

随着升级：

锁链断裂、铁片展开、符文点亮。

这样“局外成长”会成为一个非常有记忆点的界面，而不只是 Diablo 式普通技能树。

---

### 10. 增加菜单背景的“状态变化”

不要整个游戏始终使用同一张背景。

可以根据进度缓慢改变。

例如：

刚创建存档：

> 营地完整，火焰明亮。

通关第3层：

> 营地开始出现地下获得的遗物。

第6层：

> 墙面长出异常矿物。

第8层：

> 天空或者空间开始产生轻微扭曲。

第9层以后：

> 营地已经受到混沌侵蚀。

这样即使玩家没有看数字，也能感觉到：

> **我的旅程正在改变这个地方。**

这是一个成本不算特别高、但沉浸感非常高的设计。

---

### 11. 主菜单标题也可以随进度轻微变化

不是改 Logo，而是改变环境。

第一次启动：

**《噬铁者》**

背景基本静止。

玩到后期以后：

标题附近偶尔出现符文、裂纹、异色微光。

隐藏层通关之后甚至可以出现非常轻微的特殊效果。

让主菜单也成为长期反馈系统。

---

### 12. Loading 页面可以顺便承担“本局生成”

不要只显示百分比。

可以做：

```text
正在下潜……

生成地牢结构
████████████████  完成

布置事件
██████████████    完成

唤醒敌人
██████████

扭曲空间
██████
```

但这里建议主要是视觉表现，不一定真的把底层每个步骤完全暴露出来。

尤其你的地牢本身就是程序化生成，这种 Loading 表现会非常贴题。fileciteturn0file0L1172-L1176

---

### 13. 结算页面增加“这一局最有价值的信息”

不要只是一堆统计数字。

可以重点显示三件事：

> **最深抵达：第7层**

> **本局最高伤害：18,421**

> **最常用装备：噬血长剑**

或者：

> **本局吞噬：43件**

> **本局融合：21次**

这会强化《噬铁者》自己的特色，而不是让结算页看起来像普通动作游戏。

---

### 14. 结算后不要立即返回菜单

可以做三阶段：

```text
探索结束
    ↓
战斗统计
    ↓
局外奖励
    ↓
新解锁内容
    ↓
返回营地
```

但全部放在同一个页面内逐步出现，不需要四个场景。

例如：

0.0s 显示标题。

0.5s 出现层数。

1.0s 数字快速滚动。

1.8s 记忆残渣飞入右上角货币栏。

2.5s 如果有新形态，弹出解锁。

这会极大提高结算的“爽感”。

左侧可以很轻地显示：


这样暂停界面同时承担“快速查看当前局状态”的功能。

### 16. 游戏内设置必须保持暂停

这一点程序上一定注意。

流程：

```text
游戏
↓ ESC
Pause = true
↓
设置
↓ ESC
暂停菜单
↓ ESC
游戏继续
```

不能出现：

进入设置以后游戏偷偷恢复运行。

这类 Bug 在暂停菜单里非常常见。

### 17. 做真正的 UI Scale 系统

你的目标平台是 PC，而且以后还可能扩展其他平台。fileciteturn0file0L38-L63

所以不要只按照 1920×1080 写死坐标。

至少测试：

1920×1080  
2560×1440  
3840×2160  
2560×1080  
3440×1440  
1920×1200

核心内容最好限制在一个 Safe Area：

```text
16:9 核心布局区
```

21:9 只是左右展示更多背景，而不是把按钮拉到屏幕最右边。

这一点会非常影响成品感。

---

### 18. 增加 UI 字体尺寸选项

设置里建议预留：

```text
界面文字大小
小 / 标准 / 大
```

尤其你的游戏里装备、词条、吞噬、融合信息未来会很多。

仅仅改变分辨率并不能解决可读性问题。

---

### 19. 增加“减少动态效果”

设置：

```text
减少界面动态
关闭 / 开启
```

开启以后：

菜单背景大幅减少粒子。

角色切换不大幅移动。

镜头晃动减少。

页面切换动画缩短。

这既是无障碍功能，也方便低配置电脑。

---

### 20. 手柄提示不要写死 Xbox

不要永远：

> A 确认 / B 返回

最好根据设备自动变：

Xbox：

> A 确认　B 返回

PlayStation：

> ✕ 确认　○ 返回

键鼠：

> Enter 确认　Esc 返回

你的代码已经开始做输入设备识别，这一步继续完善后会明显更像正式 PC 游戏。

## 还有一个我认为非常值得做的：统一“界面动效规范”

不要每个页面自己随便 Tween。

直接规定：

| 动作 | 时间 |
|---|---:|
| Hover | 0.08～0.12s |
| 页面元素出现 | 0.18～0.25s |
| 普通页面切换 | 0.25～0.35s |
| 确认弹窗 | 0.15～0.20s |
| 角色立绘切换 | 0.20～0.30s |
| Loading 淡入 | 0.5～0.8s |
| 结算重要奖励 | 0.8～1.2s |

并且整个游戏只采用几种运动：

**淡入、横移、轻微缩放、遮罩展开。**

不要同时出现弹跳、旋转、飞入、果冻效果。

《噬铁者》的 UI 应该：

> **沉、慢、冷、硬。**

而不是手游式的“弹”。

---

## 如果再往上优化一个档次

我会把现在整个 UI 系统定义成三个核心词：

**铁。**

界面的线条、选中反馈、声音都有金属质感。

**深渊。**

背景永远比 UI 更巨大，让玩家感觉人在地下世界面前很渺小。

**吞噬。**

解锁、升级、确认、结算这些重要操作，都可以出现一种“文字或符文被黑色物质吞进去”的视觉效果。

这样以后即使别人只看到一张设置界面或者一张存档界面，也能认出来：

**这是《噬铁者》的 UI。**

目前如果按开发优先级，我建议接下来先完成 **统一 Theme → 主菜单 → 存档选择 → 存档主页 → 新游戏配置 → 暂停 → 设置 → 结算 → Loading**，最后再做动态背景和局外升级的高级演出。这样不会为了美术效果拖慢第一版可玩闭环。
