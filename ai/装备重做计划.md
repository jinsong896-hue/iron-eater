## 三、根因与修法

### 3.1 根因

生成器 `_parse_one` 是**单段式**：拿整条文本直接匹配规则。
末尾有一条宽泛兜底：

```gdscript
if nm.contains("增伤") or nm.contains("伤害"):
    return "[%d, %.4f, true]" % [SP["elem_dmg"], v]
```

任何带百分比、含「伤害/增伤」的文本都落到这里，**不管前面有没有触发从句**。
于是「生命值低于30%时，吸血效果提升20%」被压成常驻 +20% 攻击力。

### 3.2 修法：两段式

```
_parse_one(s):
    (clause, main) = _split_clause(s)      # 新增：剥离触发从句
    trig = _trigger_of_clause(clause)      # 新增：从句 → Trigger 枚举
    if clause 非空 and trig == NONE:
        return ""                          # 从句识别不了 → 报未映射，不猜
    spec = _parse_main(main)               # 复用现有规则解析主句
    if trig != ALWAYS and spec 是裸属性:
        return ""                          # 主句解出裸属性但带条件 → 报未映射
    return _wrap_with_trigger(spec, trig)  # 新增：包上触发
```

**关键不变量**：`原文含触发从句` ⟹ `结果必须带 trigger`。
违反即报未映射，**绝不静默压成常驻**。

这条不变量要写成校验器（`verify_parse_fidelity.gd` 已有雏形），
在门禁里跑，防止将来新增规则时重蹈覆辙。

## 四、分阶段执行

### 阶段 1：生成器两段式重构 + 条件型落地

**覆盖：97 件（条件压成常驻）+ 8 件（触发条件错）**

| 步骤 | 内容 |
|---|---|
| 1.1 | `gen_equipment.gd` 改两段式（见 3.2） |
| 1.2 | 实现从句 → Trigger 映射表（3.3 的 52+16 条） |
| 1.3 | 新增 6 个 Trigger 枚举 + `AffixData` 字段（阈值/距离等） |
| 1.4 | 消费点：`equipment_effects.gd` 增加对应事件钩子 |
| 1.5 | 修「击杀→命中」3 条、「凭空造触发」5 条 |
| 1.6 | 把「含从句 ⟹ 必带 trigger」写成校验器断言 |

**产出**：97+8 件的词条恢复正确语义；未映射清单会**变长**（原本被静默吞掉的
现在如实报出），这是预期行为。

### 阶段 2：职业资源点系统

**覆盖：16 条词条 + 约 10 件缺失装备**

现有 `ClassResource` 已有 `gain_on_hit` / `gain_on_kill` / `gain_on_crit_bonus` /
`gain_on_taken_pct` / `regen_per_sec`，词条能**干净映射**：

| 词条 | 映射 |
|---|---|
| 「受到伤害时获得2点怒气」 | `gain_on_taken` 增加**固定值**（现为百分比，需扩字段） |
| 「击杀敌人时获得5点怒气」 | `gain_on_kill += 5` |
| 「暴击时获得2点专注」 | `gain_on_crit_bonus += 2` |
| 「攻击命中时获得1点裁决」 | `gain_on_hit += 1` |
| 「连击时获得1点气劲」 | 新增 `gain_on_combo` |
| 「怒气获取量增加0.5%」 | 新增 `resource_gain_pct`（乘区） |
| 「每秒回复1点魔力」 | `regen_per_sec += 1` |
| 「最大怒气/…增加3%」 | `add_max_bonus(pct)`（已有接口） |

**需改**：`gain_on_taken_pct` 是百分比，而词条要的是固定值 → 加一个
`gain_on_taken_flat` 字段。

**缺失的 10 件装备**（怒气护腕/魔力护符/专注指环/裁决徽章/气劲腰带/
资源上限护符等）会随阶段 1 的生成器一起产出。

### 阶段 3：全属性通道

**覆盖：7 件**

「全属性 +N%」目前被塌缩成 `Stat.ATK`。两种做法：

- **(a) 新增 `ALL_STAT` 通道**——在 `AttributeSystem` 里对所有 11 条面板属性
  各加一次 modifier。语义准确，但要处理「属性上限」类交互。
- **(b) 生成器展开成 11 条**——直接产出 11 个 `[Stat.X, v, true]`。

**建议 (a)**：语义清晰、数据量小、图鉴显示一条而不是十一条。

### 阶段 4：修触发条件

**覆盖：8 件**（3 条「击杀→命中」+ 5 条「凭空造触发」）

纯规则修正，已并入阶段 1.5。

### 阶段 5：命中N敌触发

**覆盖：6 条**

按决策 1 **降级为额外伤害**：「裂地斩命中3个以上敌人时，伤害提升至700%」
→ 实现为「裂地斩命中 ≥3 敌时，追加一次额外范围伤害」。

需要给技能加一个「命中计数 → 条件额外效果」的钩子。

### 阶段 6：每持有X动态重算

**覆盖：5 条**

「每持有100金币 +1%攻击力」「每持有一片钥匙碎片 +2%全属性」
「每装备一件传奇装备，全属性提高8%」。

按决策 2 **动态重算**：在金币/钥匙/装备数变化时重算 modifier 并刷新
`AttributeSystem`。需要一个「装备条件修饰量重算」的入口。

### 阶段 7：状态期间免疫

**覆盖：7 条**

「石肤期间免疫击退」「大地守护期间免疫击退」「钢铁之躯期间免疫控制」
「血海狂暴期间免疫控制」等。

这些「状态」本身来自**装备技能**（如石肤胸甲的主动技能）。需要：
技能施放时给自己挂一个**具名词条**，装备词条读该具名词条判断。

### 阶段 8：元素连击 / 切换

**覆盖：5 条**

「连续攻击同一目标3次后，触发元素爆炸」「连续3次不同元素后，触发元素爆炸」
「每次攻击切换元素，切换后下次攻击+20%对应元素伤害」。

需要一个**元素序列追踪器**（记录最近 N 次攻击的元素）。

### 阶段 9：技能修饰

**覆盖：9 条**

「战吼同时嘲讽敌人1秒」「治愈术同时清除一个负面状态」「疾风步期间留下火焰路径」。
需要给 `EquipmentSkills` 表加一列 `on_cast`，由 `SkillSystem` 施法后消费。

### 阶段 10：其余杂项

剩余零散条目，逐条评估。

## 五、风险与边界

| 风险 | 说明 | 应对 |
|---|---|---|
| **未映射清单会变长** | 阶段 1 修完后，原本被静默吞掉的会如实报出 | 这是**预期行为**，不是回归。报告里说明 |
| **校验器误报** | 前几轮的校验器自己误报过（把「更具体的触发」判成错） | 每个校验器都要抽样人工核对，误报要修 |
| **消费点分散** | 6 个新 Trigger 要接到 `equipment_effects` 的多个钩子 | 统一走 `_fire(trigger)`，只加钩子不加分支 |
| **动态重算性能** | 金币每次变动都重算 modifier | 加节流：同帧内合并一次 |
| **阶段 7 依赖装备技能** | 「石肤期间」依赖石肤技能已实现 | 先确认对应技能可用，否则降级为「施放该技能后 N 秒」 |

**明确不做**：
- 非战斗事件（开宝箱/出售装备/回收标枪/窃取成功/进未探索房间）
- 数值平衡（一律按文档原值）
- 装备技能表本身的重做（另开一轮）
