## 一、整个菜单建议做成这套结构

```text
启动游戏
   ↓
【主菜单】
   ├─ 开始游戏
   │      ↓
   │  【存档选择】
   │      ├─ 存档 01
   │      ├─ 存档 02
   │      ├─ 存档 03
   │      └─ 空存档 → 添加存档
   │
   │      点击已有存档
   │          ↓
   │     【存档主页】
   │          ├─ 开始游戏
   │          │     ↓
   │          │  有未结束游戏？
   │          │    ├─ 是 → 是否结束上一局？
   │          │    └─ 否
   │          │
   │          │     ↓
   │          │ 【新游戏配置】
   │          │     ├─ 选择角色
   │          │     ├─ 选择模式
   │          │     ├─ 选择难度
   │          │     └─ 开始
   │          │
   │          ├─ 继续游戏
   │          ├─ 升级
   │          └─ 退出当前存档
   │
   ├─ 设置
   └─ 退出游戏

游戏中
   ↓ ESC
【暂停菜单】
   ├─ 继续游戏

   └─ 退出游戏
```

这套结构最大的优点是：**主菜单管理“玩家档案”，存档主页管理“这个玩家档案里的游戏内容”，游戏内暂停菜单只处理当前这一局。** 不容易乱。

# 二、第一页：游戏主菜单

建议画面比例大概这样：

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                                                              │
│               《噬 铁 者》                                   │
│                                                              │
│        大面积动态美术 / 世界观场景                            │
│                                                              │
│          主角 / 地牢 / 巨型机械遗迹             开始游戏     │
│                                                 设置         │
│                                                 退出游戏     │
│                                                              │
│                                                              │
│                                               V0.1.0         │
└──────────────────────────────────────────────────────────────┘
           左侧约 70%                         右侧约 30%
```

### 美术画面

不要让 UI 抢画面。

你的游戏本身定位是“暗黑哥特 + 克苏鲁元素，而且随着地牢深入逐渐诡异化”。fileciteturn0file0L75-L78

所以开始页面可以直接建立一个非常强的第一印象：

**左下：** 主角背影。

**中央：** 巨大的地牢入口、废弃熔炉或者机械遗迹。

**远处：** 隐约出现不可名状的巨大轮廓。

**环境：** 铁锈、锁链、废弃机械、蒸汽、灰尘颗粒。

画面可以有很轻微的动态：

火星飘落、雾气移动、锁链晃动、远处火光闪烁。

但一定不要做得特别吵。

因为这里的目标不是炫 UI，而是：

> **第一次打开游戏，玩家就知道这是一个阴暗、危险、关于“铁”和“吞噬”的世界。**

# 三、右侧菜单不要做成按钮框

这一点我比较建议你坚持。

不要：

```text
┌───────────┐
│ 开始游戏  │
└───────────┘
```

而是直接使用文字：

```text
开始游戏

设置

退出游戏
```

鼠标悬停或者键盘选中后：

```text
> 开始游戏
```

或者：

```text
开始游戏  ━━━━━
```

再配一个非常轻微的金属摩擦音。

这样比一排黑色矩形框更符合《噬铁者》的气质。

# 五、已有存档应该显示什么

不要显示太多。

一个存档建议只展示：

| 内容 | 示例 |
|---|---|
| 存档编号 | 存档 01 |
| 当前代表角色 | 战士 · 狂怒之刃 |
| 总游戏时间 | 12h 43m |
| 最高地牢层数 | 第 6 层 |
| 剧情进度 | 第 2 章 |
| 最后游戏时间 | 2026/08/12 |
| 是否存在进行中的一局 | 地牢探索中 |

最后一项很重要。

例如：

```text
存档 01

战士 · 狂怒之刃
游戏时间：12h 43m
最高抵达：第 6 层

● 存在未完成的探索
```

这样玩家还没进入存档，就已经知道里面有没有可以“继续游戏”的内容。

# 八、「继续游戏」的状态非常重要

按照你的要求：

### 有进行中的游戏

显示：

```text

```

可以正常点击。

下面附一行小字：

```text

游戏时间 31:42
```

### 没有进行中的游戏

显示：

```text

```

但文字变灰。

鼠标经过：

```text

```

灰掉比隐藏好。

因为隐藏以后，玩家会不知道这个游戏到底有没有“继续游戏”功能。

# 十四、ESC规则建议统一

你提出“ESC返回上一级”是很好的，但必须从一开始就统一。

建议最终规则只有这一套：

- **主菜单：** ESC 无效果，或者弹“是否退出游戏”；我更建议无效果。
- **存档选择：** ESC → 主菜单。
- **存档主页：** ESC → 存档选择。
- **新游戏配置：** ESC → 存档主页。
- **升级：** ESC → 存档主页。
- **设置：** ESC → 打开设置前的页面。
- **游戏中：** ESC → 暂停游戏。
- **暂停状态再次 ESC：** 关闭暂停菜单，继续游戏。

这样玩家永远不用学习新的操作规则。

# 十五、游戏内暂停菜单

游戏内按 ESC：

首先：

```text
get_tree().paused = true
```

游戏完全停止。

然后中央或者右侧弹：

```text
                暂停

              继续游戏

                设置

              退出游戏
```

这里我建议把你说的“退出游戏”再拆清楚一点。

直接写“退出游戏”容易让玩家理解成关闭 EXE。

最好点击后再弹：

```text
退出当前游戏？

[返回主菜单]
[退出至桌面]
[取消]
```

其中：

### 返回主菜单

保存当前可以保存的数据，然后回到当前存档主页或者主菜单。

### 退出至桌面

关闭游戏。

这两个最好不要混在一起。

# 十七、三个存档的数据结构也可以现在直接定下来


```text
SaveData
├─ save_id
├─ create_time
├─ last_play_time
├─ total_play_time
│
├─ progression
│   ├─ story_progress
│   ├─ highest_floor
│   ├─ unlocked_classes
│   ├─ unlocked_forms
│   └─ talents
│
├─ currencies
```

**继续游戏 = 可点击**
