# 元素词条与自有词条重做计划

> 日期：2026-09-23
> 触发：用户指出「每个属性伤害是按名词设计里的元素属性去做的，不能统一概括；
> 火系法杖是增加火属性伤害、攻击附带火属性」+「存在大量装备没有自有词条」。

## 一、问题一：具体元素被塌缩成全局键

### 1.1 根因

`tools/gen_equipment.gd:100-105` 把所有具体元素**映射到同一个键**：

```gdscript
"元素伤害": "elem_dmg", "火焰伤害": "elem_dmg", "冰霜伤害": "elem_dmg",
"雷电伤害": "elem_dmg", "毒素伤害": "elem_dmg", "大地伤害": "elem_dmg",
"土元素伤害": "elem_dmg", "风元素伤害": "elem_dmg", "暗影伤害": "elem_dmg",
"远程伤害": "elem_dmg", "范围伤害": "elem_dmg", "陷阱伤害": "elem_dmg",
"投射物伤害": "elem_dmg", "被冻结敌人受到伤害": "elem_dmg",
"元素抗性": "elem_resist", "异常状态抗性": "elem_resist", "护盾强度": "elem_resist",
```

**后果**：烈焰法杖与寒霜法杖的吞噬词条生成出来**一字不差**（都是 `[[117,0.01]]`），
元素区别在数据层就消失了。而且「远程/范围/陷阱/投射物伤害」**根本不是元素**，
「异常状态抗性/护盾强度」**不是元素抗性**——它们被塞进了错误的通道。

|---|---|---|---|

### 1.3 受影响装备（实测）

- 含 `elem_dmg(117)` 的策划装备：**141 件**
- 含 `elem_resist(106)` 的策划装备：**45 件**
- 两者都有：8 件

**注意**：`own_affixes` 里的 `BONUS_ELEMENT`（`[[3,"fire",0.5]]`）**是对的**——

## 二、问题二：大量装备没有自有词条

### 2.1 实测数据

| 项 | 数量 |
|---|---|
| 策划表装备总数 | 349 |
| **自有词条为空** | **135（38.7%）** |
| 融合词条为空 | 56 |
| 吞噬词条为空 | 2 |

### 2.2 根因：技能表与装备表断开

349 件里 **137 件带装备主动技能**（`EquipmentSkills`），其中：

- **129 件的自有词条为空** —— 技能表里有技能，装备模板里没记
- 只有 8 件非空

**规格里这些装备的自有词条写的就是技能本身**：

```
17. 元素洪流（史诗·法杖）
自有词条：主动技能"元素洪流"——释放随机元素洪流，对路径敌人造成180%法强对应元素伤害，冷却12秒
```

生成器把这类词条识别成了「技能」并单独放进 `EquipmentSkills`，
但**没有在 `own_affixes` 里留下任何痕迹** → 图鉴/背包的「【自有词条】」
显示为空，玩家看不出这件装备为什么有技能。

### 2.3 真根因：正则误判，不是规格缺失

用户指出「文档里明确所有装备词条都是满的」——**核实为真**。
TSV 规格表里 **368 行 × 三列词条全部非空**，一条都不缺。

真正的根因是 `gen_equipment.gd:1562` 的 `_RE_SKILL_NOTE` 正则：

```
^(?:治愈术|战吼|护盾|陷阱|…|光环).*(?:期间|同时|触发时|被击破时|存在时|留下|释放|引爆|翻倍|清除|满层时)
```

第二个 `.*` 会把**条件型词条**整个吃掉——「护盾**被击破时**…」
「陷阱**触发时**…」「旋风斩**期间**…」「治疗**同时**…」全部命中，
于是被判为「装备技能的修饰」并**静默丢弃**。

**实测误判规模**：

| 列 | 非空 | 被误判为技能 |
|---|---|---|
| 第 6 列（自有） | 368 | 5 |
| 第 7 列（吞噬） | 368 | 0 |
| 第 8 列（融合） | 368 | **55** |

**合计 60 条词条被静默丢弃。**

### 2.4 为什么报告显示「一切正常」

`tools/data/unmapped_report.txt` 当前内容是：

```
=== 无法自动映射的词条：0 条去重 ===
=== 装备技能修饰（已跳过，不属于词条）：202 条 ===
```

被误判的 60 条**计入了「装备技能修饰」**——那个分类本意是「这条词条是
技能数值修饰，不属于词条层级」，看起来像正常跳过。**报告全绿，数据在丢。**

这正是「假绿灯」的典型形态：**校验指标本身错了**，不是校验没跑。

### 2.5 空词条的完整构成（修正后）

```
135 件空自有词条 = 129（带装备技能，见 §2.6）
                 +   6（正则误判，见 §2.3）

 56 件空融合词条 =  55（正则误判，见 §2.3）
                 +   1（待核）
```

### 2.6 技能型自有词条（129 件）

349 件里 **137 件带装备主动技能**，其中 129 件的 `own_affixes` 为空。

规格里这些装备的自有词条写的就是技能本身：

```
17. 元素洪流（史诗·法杖）
自有词条：主动技能"元素洪流"——释放随机元素洪流，对路径敌人造成180%法强对应元素伤害，冷却12秒
```

生成器把它识别成「技能」并放进 `EquipmentSkills`，
但**没有在 `own_affixes` 里留下痕迹** → 图鉴/背包的「【自有词条】」显示为空。

## 三、执行计划

### 阶段 A：元素通道拆分（数据模型 + 引擎）

**A1. 新增按元素区分的修饰量键**

`equipment_manager.special_modifiers()` 的输出字典增加：

```
fire_dmg_pct, frost_dmg_pct, static_dmg_pct, earth_dmg_pct,
wind_dmg_pct, poison_dmg_pct, shadow_dmg_pct,      # 七种增伤
fire_resist_pct, ... poison_resist_pct, shadow_resist_pct,  # 七种抗性
```

保留 `elem_dmg_pct` / `elem_resist_pct` 作为**全局**通道
（规格里确有「元素伤害增加 N%」「元素抗性 N%」的写法）。

**A2. `SPECIAL_STAT` 扩展**

`data/equipment/equipment_db.gd:74` 的枚举表增加 7×2 个条目
（enum 值从 121 起，避免与现有 100-120 冲突）。

**A3. 生成器规则修正**

`tools/gen_equipment.gd` 的 `KEY_ALIAS` 表改为：

```gdscript
# 具体元素 → 各自的键（不再塌缩）
"火焰伤害": "fire_dmg", "冰霜伤害": "frost_dmg", ...
# 全局元素保留
"元素伤害": "elem_dmg",
# **移出元素通道**——它们不是元素
"远程伤害" / "范围伤害" / "陷阱伤害" / "投射物伤害" / "被冻结敌人受到伤害"
"异常状态抗性" / "护盾强度"
```

后两类需要**新通道**（见待确认 ②）。

**A4. 引擎消费点**

- `player.gd:1094`：改为按 `attack_element` 取对应元素的增伤
- `player.gd:1832`：改为按来袭伤害的元素取对应抗性
- 需要有「当前伤害的元素」这个上下文——`DamagePipeline.elemental_attack`
  已接收 `element` 参数，改造成本可控

**A5. 重新生成 + 校验**

跑 `tools/gen_equipment.gd` 重生成 `equipment_db.gd`，
并新增校验：**六系法杖的吞噬词条必须互不相同**（当前一字不差）。

### 阶段 B：词条解析修复与补全

**B1. 修 `_RE_SKILL_NOTE` 正则**（**先做，不依赖任何决策**）

当前正则的第二个 `.*` 把条件型词条整个吃掉。修法：把它从
「开头词 + 任意内容 + 条件词」改成**只匹配真正的技能修饰句式**——
即必须出现「技能名 + 伤害/冷却/持续/效果」这类**数值修饰**特征，
而不是靠「期间/触发时」这种**条件从句**特征（条件从句是正常词条的常见写法）。

**修完后立即重生成，60 条词条自动恢复**——这一步是止血，先做。

**B2. 技能型自有词条**（129 件）

生成器在写 `EquipmentSkills` 的同时，往 `own_affixes` 补一条
`AffixData`，承载「本装备提供主动技能 X」。

需要一个新 `Operation`（如 `GRANT_SKILL`）或复用现有描述型词条——
**建议新增 `GRANT_SKILL`**，因为它的语义是「提供技能」而不是数值修饰，
塞进属性通道会让 `AttributeSystem` 收到无意义的 modifier。

**B3. 「核心机制：」字段名**（3 件）

生成器需同时识别「自有词条：」与「核心机制：」两个字段名。
实测只影响 `护盾爆裂(O054)`、`召唤领主(O056)`、`资源爆发(P105)`。

**B4. 修完后重跑校验**

`unmapped_report.txt` 的「装备技能修饰（已跳过）」数量应从 202 条
**显著下降**——那 202 条里有 60 条是误判。修完后剩余的才是真技能修饰。

### 阶段 C：验证

**C1.** 新增测试：六系法杖的吞噬/融合词条两两不同；`fire_dmg_pct` 只放大火伤。
**C2.** 新增测试：带技能的装备 `own_affixes` 非空。
**C3.** 校验脚本：统计自有词条为空的装备数，**必须为 0**（或全部有明确理由）。
**C4.** 全量门禁 `bash tests/run_all.sh`。

## 四、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **重生成覆盖手工修正** | `equipment_db.gd` 由生成器产出，重跑会覆盖 | 生成器是唯一数据源，手工改动一律回到生成器 |

| **暗影不是六元素** | 规格里 33 处「暗影伤害」，但 `ElementDefs.Elem` 没有暗影 | 见待确认 ① |

主动技能"灵魂爆发"——消耗所有灵魂层数，每层造成40%攻击力伤害（最多10层），冷却30秒

**关键观察**：C 组的「灵魂」**完全是叠层资源机制**（击杀攒层 → 满层爆发），
与元素系统无关。A 组只有 3 条真正的「暗影伤害 N%」。
B 组是技能效果描述，不是装备词条。

**决策选项**：

| 选项 | 说明 | 影响面 |
|---|---|---|
| (a) 暗影作为第 7 种元素 | 需补叠层/DOT/阈值机制设计（名词设计分册只定义了 6 种） | 大——要新增一整套元素机制 |
| (b) 暗影 = 法术伤害的一种，走 `magic_dmg_pct` | 不参与元素叠层 | 小——只需一个全局法术增伤键 |
| (c) 独立键 `shadow_dmg_pct`，不参与元素叠层 | 保留语义区分，只做增伤 | 中——1 个新键 + 消费点 |

**「灵魂」建议单列为资源叠层系统**（与元素无关），不混进元素决策。

**E 组 · 防御类（9 条）**

```
异常状态抗性增加1% / 2% / 3%
角色异常状态抗性增加0.5%
护盾强度+5% / 护盾强度增加0.5% / 1% / 2% / 3%
护盾获取量增加0.5% / 护盾获取量增加2%
```

**决策选项**：

| 概念 | 建议 | 理由 |
|---|---|---|
| 远程/范围/陷阱/投射物伤害 | 新增 `ranged_dmg_pct` / `aoe_dmg_pct` / `trap_dmg_pct` / `projectile_dmg_pct` | 规格里明确是独立维度，19+ 条在用 |
| 被冻结敌人受到伤害 | 新增条件增伤键，或归入已有的「易伤」通道 | 是**条件**增伤，不是元素 |
| 异常状态抗性 | 新增 `debuff_resist_pct` | 与元素抗性语义不同 |
| 护盾强度 / 护盾获取量 | 合并为 `shield_power_pct` | 两者语义接近，都是「护盾更厚」 |

**注意**：「陷阱伤害减少2%」是**负面**词条（可能是给敌方的或设计失误），需确认。
