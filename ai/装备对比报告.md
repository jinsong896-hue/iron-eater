## 二、最大问题：条件型词条被压成常驻属性（97 件 / 109 条）

### 2.1 问题

文档里大量词条是**条件型**的——含一个触发从句（「X 时，」「X 后，」）。
而**常驻属性表达不了触发语义**：若解析结果是一条裸属性
（`[Stat.X, v, bool]` 或 `[NNN, v, true]`），触发条件就被**静默丢弃**，
词条变成**无条件永久生效**。

实测：819 条裸属性解析结果里，**109 条的原文带触发从句**。

### 2.2 典型样本

```
原文  生命值低于30%时，吸血效果提升20%
解析  [Stat.ATK, 0.2000, true]        ← 永久 +20% 攻击力，且「低于30%」丢失

原文  生命值低于50%时，免疫控制效果
解析  [112, 0.50, true]               ← 变成永久 +50% 控制抗性

原文  击杀敌人后，移动速度增加20%，持续3秒
解析  [Stat.SPD, 0.2000, true]        ← 永久 +20% 移速，触发与时长全丢

原文  每次冲刺叠加1层"踏虚"（最多3层），每层+5%闪避
解析  [111, 0.0500, true]             ← 变成永久 +5% 闪避，叠层机制消失

原文  隐身期间免疫控制
解析  [112, 0.30, true]               ← 变成永久 +30% 控制抗性

原文  召唤物存在时，自身攻击力提高25%
解析  [106, 0.05, true]               ← 变成 +5% 元素抗性 —— 通道也错了

原文  背刺击杀敌人时，获得3秒隐身
解析  [111, 0.2000, true]             ← 变成永久 +20% 闪避

原文  生命满时，回复转化为护盾（最多10%最大生命）
解析  [106, 0.1000, true]             ← 变成永久 +10% 元素抗性
```

### 2.3 为什么这是最严重的

- **没实现**（未映射）= 词条无效果，玩家看不出异常
- **压成常驻** = 词条以**错误语义永久生效**，数值还可能很强

而且这类错误**在前两轮报告里全部显示为「已解析」**——报告全绿，数据是错的。
「召唤物存在时攻击力+25%」→「+5% 元素抗性」尤其典型：连**通道都换了**。

### 2.4 按从句类型分布

| 类型 | 条数 | 样本 |
|---|---|---|
| 生命/血量条件 | 11 | 「生命值低于30%时，吸血效果提升20%」 |
| 击杀条件 | 11 | 「击杀敌人后，移动速度增加20%，持续3秒」 |
| 受击/格挡/闪避 | 15 | 「受到近战攻击时，反弹30%伤害给攻击者」 |
| 施法/使用技能 | 3 | 「使用技能后，下次技能冷却-1秒（最多叠3层）」 |
| 召唤物/存在期间 | 18 | 「隐身期间免疫控制」「召唤物存在时，自身攻击力提高25%」 |
| 其他（概率、距离、目标状态…） | 51 | 「距离目标超过5米时，伤害增加3%」 |

## 四、根因

### 4.1 数据源不全（已修）

`equipment_spec.tsv` 原先只有 349 条而文档有 400 条——51 件从未进入流水线。
已由 `tools/extract_equipment_spec.gd` 重建（提交 `fb0ae5d3`）。

### 4.2 生成器的兜底规则「吞掉」条件语义

生成器末尾有一条宽泛兜底：

```gdscript
if nm.contains("增伤") or nm.contains("伤害"):
    return "[%d, %.4f, true]" % [SP["elem_dmg"], v]
```

任何带百分比、含「伤害/增伤」的文本都会落到这里，**不管前面有没有触发从句**。
「生命值低于30%时，吸血效果提升20%」正是这样被压成常驻属性的。

### 4.3 校验维度不足（已补）

- 第一轮只统计「无法映射的条数」→ 漏掉所有「解析了但解错」的
- 第二轮补了「解析忠实度」（触发条件/叠层/属性范围/数值）→ 但只覆盖 3 种触发词
- 第三轮补「条件从句全量扫描」→ 才暴露最大的一类

现已有三个校验工具（见第六节）。

## 五、执行建议

| 顺序 | 工作 | 覆盖 | 说明 |
|---|---|---|---|
| 1 | **条件型解析重构** | 97 件 | 核心：凡原文带触发从句，**禁止**落到裸属性兜底。要么产出带 `trigger` 的触发型词条，要么明确报「未实现」 |
| 2 | **职业资源点系统** | 16 条 + ~10 件 | 5 职业各一套。缺口最大且是其他机制的前置 |
| 3 | **全属性通道** | 7 件 | 新增「全属性 +N%」通道，或展开成 11 条面板属性 |
| 4 | **修触发条件** | 3 件 | 纯规则修正 |
| 5 | **技能修饰**（技能表加一列） | 9 条 | 需 `EquipmentSkills` 加 `on_cast` 列 |
| 6 | **元素终焉 / 能量储存 / 扩散 / 陷阱 / 杂项** | 19 条 | 逐族实现 |

**第 1 项是纯 bug 修复、无新系统、收益最大（97 件）**，应优先。
第 1+3+4 项（全是修复，不引入新机制）即可覆盖 **103 件**。
