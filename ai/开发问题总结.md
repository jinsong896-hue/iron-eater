# 《噬铁者》开发问题总结文档

> 记录开发 IronEater Creator 框架和房间编辑器过程中遇到的所有技术问题及解决方案。

---

## 一、编辑器插件开发

### 1. @tool 脚本中 @onready 变量为 null

**现象**：插件按钮点击无响应，`Cannot call method 'clear' on a null value`

**根因**：`setup()` 由插件的 `_enter_tree()` 调用，此时节点尚未进入场景树，`@onready` 变量未初始化。

**解决**：`setup()` 只存 `editor_interface` 引用，所有 UI 操作移到 `_ready()` 中。

### 2. CanvasLayer 按钮在 @tool 模式不可交互

**现象**：场景中的 CanvasLayer 按钮在编辑器 2D 视口中无法点击

**根因**：Godot 编辑器捕获 2D 视口鼠标事件，Control 节点不接收输入

**解决**：改用 EditorPlugin 右侧停靠面板（`add_control_to_dock`），面板中的按钮可正常交互

### 3. @tool 动态创建 UI 元素不可靠

**现象**：`Button.new()` / `Label.new()` 动态创建的控件文字飞出界面、按钮无响应

**根因**：在 `@tool` 脚本中动态创建 Control 节点时，布局和渲染不稳定

**解决**：所有 UI 预建在 `.tscn` 场景文件中，脚本只处理信号回调

### 4. EditorPlugin dock 调用 scene root 方法失败

**现象**：插件面板调用 `_editor_interface.get_edited_scene_root().save_room()` 无响应

**根因**：scene root 的 `@tool` 脚本方法在插件上下文中无法可靠调用

**解决**：插件直接操作 scene root 的子节点（`get_children()`），不通过方法调用

### 5. ResourceSaver.save() 在编辑器插件中卡死

**现象**：点击保存后状态显示"正在写入..."然后永远卡住

**根因**：`ResourceSaver.save()` 在编辑器上下文中触发文件系统扫描，可能阻塞

**解决**：改用 `FileAccess.open()` + `store_string()` 手动写 `.tres` 文本文件

## 二、GDScript 类型系统

### 6. class_name 在跨文件引用时找不到

**现象**：`Parse Error: Could not find type "RoomEditorData" in the current scope`

**根因**：Godot 的 `class_name` 注册依赖于脚本加载顺序，跨目录引用时可能未加载

**解决**：
- 数据类添加 `@tool` 注解（如 `RoomEditorData`、`AnimationSetData`）
- 使用 `Resource.new()` + `set_script(preload(...))` 替代 `ClassName.new()`
- 导出变量用 `Resource` 类型替代具体类名
- 属性和方法用 `.get()` / `.set()` / `.call()` 替代直接访问

### 7. for 循环中 `is` 检查不改变静态类型

**现象**：`Cannot infer the type of "sid" variable`

**根因**：`for child in root.get_children()` 中 `child` 静态类型是 `Node`，即使 `if child is TileMapLayer` 检查通过，编译器仍无法推断

**解决**：显式转换 `var layer := child as TileMapLayer`

### 8. 三元运算符类型推断失败

**现象**：`Cannot infer the type of "mesh" variable`

**根因**：`var mesh := res.instantiate() if res is PackedScene else null` 中 `instantiate()` 返回类型无法被三元运算符推断

**解决**：改为 if-else 语句

### 9. Resource 内置属性名冲突

**现象**：`Member "resource_name" redefined (original in native class 'Resource')`

**根因**：`Resource` 类有内置 `resource_name` 属性，子类不能重定义

**解决**：重命名为 `res_name`

### 10. `@export_enum` 与 `var` 分离时的解析问题

**现象**：`@export_enum` 声明的变量在其他脚本中无法访问

**根因**：`@export_enum` 和 `var` 声明必须紧邻，中间不能有空行或注释

**解决**：保持 `@export_enum(...)\nvar name: String` 格式

## 三、文件格式与编码

### 11. CRLF vs LF 行尾问题

**现象**：`Edit` 工具反复报 `String to replace not found in file`

**根因**：Windows Godot 编辑器保存文件时使用 CRLF，而 Claude 的 Edit 工具通常匹配 LF

**解决**：编辑前先用 `tr -d '\r'` 转换为 LF，编辑后用 Git 提交

### 12. .tres 文件手动写入格式错误

**现象**：`Parse Error: Expected value, got '('`

**根因**：手动写的 `.tres` 中 `(0, 0)` 格式不被 Godot 解析器识别

**解决**：使用完整格式 `Vector2i(0, 0)` 和 `Vector2(0.0, 0.0)`

### 13. heredoc 残留 `ENDOFFILE` 在文件中

**现象**：`Parse Error: Unexpected identifier "ENDOFFILE" in class body`

**根因**：bash heredoc 语法错误导致 `ENDOFFILE` 字符串被写入文件末尾

**解决**：检查文件末尾，删除残留的 `ENDOFFILE` 行

### 14. sed 命令破坏代码

**现象**：sed 修改后出现 `tfor` 等无意义标识符、代码结构错乱

**根因**：sed 在 CRLF 文件上操作时，`\r` 被当作普通字符，导致替换位置错位

**解决**：避免用 sed 修改 GDScript 文件，优先使用 `Write` 工具重写整个文件

## 四、数据序列化

### 15. 手动 .tres 序列化遗漏属性

**现象**：`_sources` 数组保存后加载为空

**根因**：`_serialize()` 函数只写了 `_cells` 和 `_atlas`，没有写 `_sources`

**解决**：在 `_serialize()` 中为 `_sources` 数组添加写入逻辑

### 16. ResourceSaver 与手动序列化的数据不一致

**现象**：测试用 `ResourceSaver.save()` 写入的文件，`_sources` 丢失

**根因**：`ResourceSaver.save()` 只保存 `@export` 变量，非导出变量不保存

**解决**：所有需要持久化的字段都添加 `@export`，或统一使用手动序列化

### 17. 加载旧格式 .tres 文件崩溃

**现象**：`Invalid type in function: Cannot convert argument 5 from Nil to Array`

**根因**：旧格式文件没有 `_sources` 字段，`data.get()` 返回 null

**解决**：添加 `_safe_arr()` 函数，将 null 转为空数组 `[]`

## 五、编辑器架构

### 18. 多个入口导致混乱

**现象**：房间编辑器有两个插件（独立插件 + IronEater Studio），功能重复

**根因**：逐步开发时未清理旧代码

**解决**：禁用独立插件，统一到 IronEater Studio 的标签页中

### 19. 编辑器功能跨场景调用失败

**现象**：插件面板的按钮无法操作 2D 视口中的 TileMapLayer

**根因**：插件通过 `get_edited_scene_root()` 访问场景节点，但场景可能未正确打开

**解决**：添加 `_root()` 的空值检查和"请先打开 room_editor.tscn"提示

### 20. Hub 按钮 vs 标签页的抉择

**现象**：Hub 主菜单按钮全部无响应

**根因**：`@tool` 动态创建的 UI 在编辑器中不可靠

**解决**：回归 TabContainer 标签页方案，所有面板预建在 `.tscn` 中

## 六、开发流程教训

### 21. 不要用 sed 修改 GDScript

**教训**：sed 在 CRLF 文件上不可靠，会导致隐藏的语法错误

**正确做法**：使用 `Write` 工具重写整个文件，或先用 `Read` 确认内容再用 `Edit` 精确修改

### 22. 每次修改后必须跑测试

**教训**：多次提交后发现 sed 修改引入了新 bug

**正确做法**：
```bash
GODOT="F:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64.exe"
"$GODOT" --headless --path . --script res://tests/test_room.gd
"$GODOT" --headless --path . res://tests/test_dungeon.tscn
```

### 23. 先设计数据格式再写代码

**教训**：`_sources` 数组后期才添加，导致大量兼容性修复

**正确做法**：数据类设计时一次性确定所有字段，包括 `@export` 注解

### 24. 编辑器功能在面板中实现，不在场景中

**教训**：`room_editor.tscn` 的 CanvasLayer UI 和插件面板功能重复

**正确做法**：场景只放 TileMapLayer，所有编辑功能在插件面板中

## 七、当前已知限制

| 限制 | 说明 |
|---|---|
| 插件面板宽度固定 | TabContainer 在右侧 dock 中宽度受限 |
| @tool 脚本不能热重载 | 修改 @tool 脚本后需重启 Godot |
| 3D SubViewport 在编辑器中不渲染 | CharacterRenderer 只在游戏运行时显示 |
| 门精灵图需手动放置 | 没有精灵图时自动使用色块回退 |
| 数据文件无版本管理 | 旧格式需要 `_safe_arr` 兼容处理 |
