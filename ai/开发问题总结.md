# 《噬铁者》开发问题总结文档

> 记录 IronEater Creator 框架和房间编辑器开发过程中遇到的所有技术问题及解决方案。
> **优先级说明**：🔴 致命（会导致编译失败/运行时崩溃）、🟠 严重（功能不可用）、🟡 一般（影响开发效率）

---

## 开发前必读检查清单

修改任何 `.gd` 文件前，逐条确认：

- [ ] 🔴 `@tool` 脚本的 `setup()` 只存引用，所有初始化放 `_ready()`
- [ ] 🔴 跨文件引用 `class_name` 前，被引用类必须加 `@tool` 注解
- [ ] 🔴 `for child in get_children()` 中用 `var layer := child as TileMapLayer` 显式转换
- [ ] 🔴 不要用 `ResourceSaver.save()` 在插件中保存，用 `FileAccess` + 手动序列化
- [ ] 🔴 不要用 sed 修改 GDScript，用 `Write` 工具重写整个文件
- [ ] 🔴 所有编辑器 UI 预建在 `.tscn` 中，不要用 `Button.new()` 动态创建
- [ ] 🟠 提交前先跑 `test_room.gd` 和 `test_dungeon.gd`
- [ ] 🟠 `.tres` 手动序列化时 Vector2i 用 `Vector2i(x, y)` 格式，不用 `(x, y)`
- [ ] 🟠 加载旧数据时用 `_safe_arr()` 处理 null 字段
- [ ] 🟡 编辑前先用 `tr -d '\r'` 转换 CRLF → LF
- [ ] 🟡 新增 `@export` 字段后同步更新 `_serialize()` 函数

---

## 一、编辑器插件开发

### 🔴 1. @tool 脚本中 @onready 变量为 null

**现象**：插件按钮点击无响应，`Cannot call method 'clear' on a null value`

**根因**：`setup()` 由插件的 `_enter_tree()` 调用，此时节点尚未进入场景树，`@onready` 变量未初始化。

**解决**：`setup()` 只存 `editor_interface` 引用，所有 UI 操作移到 `_ready()` 中。

**正确写法**：
```gdscript
func setup(editor_interface: EditorInterface) -> void:
    _editor_interface = editor_interface  # 只存引用

func _ready() -> void:
    _refresh_list()  # 所有初始化在这里做
```

---

### 🔴 2. 编辑器插件中 ResourceSaver.save() 卡死

**现象**：点击保存后状态显示"正在写入..."然后永远卡住

**根因**：`ResourceSaver.save()` 在编辑器上下文中触发文件系统扫描，可能阻塞主线程

**解决**：改用 `FileAccess.open()` + `store_string()` 手动写 `.tres` 文本文件

**正确写法**：
```gdscript
var file := FileAccess.open(path, FileAccess.WRITE)
if file == null: return
file.store_string(_serialize(data))
file.close()
```

---

### 🔴 3. @tool 动态创建 UI 元素不可靠

**现象**：`Button.new()` / `Label.new()` 动态创建的控件文字飞出界面、按钮无响应

**根因**：在 `@tool` 脚本中动态创建 Control 节点时，布局和渲染在编辑器模式下不稳定

**正确做法**：所有 UI 预建在 `.tscn` 场景文件中，脚本只处理信号回调

---

### 🟠 4. CanvasLayer 按钮在 @tool 模式不可交互

**现象**：场景中的 CanvasLayer 按钮在编辑器 2D 视口中无法点击

**根因**：Godot 编辑器捕获 2D 视口鼠标事件，Control 节点不接收输入

**解决**：改用 EditorPlugin 右侧停靠面板（`add_control_to_dock`），面板中的按钮可正常交互

---

### 🟠 5. EditorPlugin dock 调用 scene root 方法失败

**现象**：插件面板调用 `_editor_interface.get_edited_scene_root().save_room()` 无响应

**根因**：scene root 的 `@tool` 脚本方法在插件上下文中无法可靠调用

**解决**：插件直接操作 scene root 的子节点（`get_children()`），不通过方法调用

---

### 🟡 6. Hub 按钮 vs 标签页的抉择

**现象**：Hub 主菜单按钮全部无响应

**根因**：`@tool` 动态创建的 UI 在编辑器中不可靠

**解决**：使用 TabContainer 标签页方案，所有面板预建在 `.tscn` 中

---

## 二、GDScript 类型系统

### 🔴 7. class_name 在跨文件引用时找不到

**现象**：`Parse Error: Could not find type "RoomEditorData" in the current scope`

**根因**：Godot 的 `class_name` 注册依赖于脚本加载顺序，跨目录引用时可能未加载

**解决方案（按优先级）**：
1. **数据类加 `@tool`**：`@tool\nclass_name RoomEditorData\nextends Resource`
2. **用 `Resource` 类型替代具体类名**：`@export var editor_data: Resource = null`
3. **用 `Resource.new() + set_script(preload(...))` 替代 `ClassName.new()`**
4. **属性和方法用 `.get()` / `.set()` / `.call()` 替代直接访问**

---

### 🔴 8. for 循环中 `is` 检查不改变静态类型

**现象**：`Cannot infer the type of "sid" variable`

**根因**：`for child in root.get_children()` 中 `child` 静态类型是 `Node`，即使 `if child is TileMapLayer` 检查通过，编译器仍无法推断

**正确写法**：
```gdscript
for c in root.get_children():
    if c is TileMapLayer:
        var layer := c as TileMapLayer  # 显式转换
        layer.clear()
```

---

### 🟠 9. Resource 内置属性名冲突

**现象**：`Member "resource_name" redefined (original in native class 'Resource')`

**根因**：`Resource` 类有内置 `resource_name` 属性，子类不能重定义

**解决**：重命名为 `res_name`

---

### 🟡 10. 三元运算符类型推断失败

**现象**：`Cannot infer the type of "mesh" variable`

**根因**：`var mesh := res.instantiate() if res is PackedScene else null` 中 `instantiate()` 返回类型无法被三元运算符推断

**解决**：改为 if-else 语句

---

## 三、文件格式与编码

### 🔴 11. 不要用 sed 修改 GDScript 文件

**现象**：sed 修改后出现 `tfor`、`characteracters` 等无意义标识符

**根因**：sed 在 CRLF 文件上操作时，`\r` 被当作普通字符，导致替换位置全部错位

**正确做法**：使用 `Write` 工具重写整个文件，或先用 `Read` 确认内容再用 `Edit` 精确修改

---

### 🟠 12. CRLF vs LF 行尾问题

**现象**：`Edit` 工具反复报 `String to replace not found in file`

**根因**：Windows Godot 编辑器保存文件时使用 CRLF，而 `Edit` 工具匹配 LF

**解决**：编辑前先用 `tr -d '\r' < file.gd > /tmp/fix.gd && mv /tmp/fix.gd file.gd` 转换为 LF

---

### 🔴 13. .tres 文件手动写入格式错误

**现象**：`Parse Error: Expected value, got '('`

**根因**：手动写的 `.tres` 中 `(0, 0)` 格式不被 Godot 解析器识别

**正确格式**：
```
Vector2i(0, 0)    ← 正确
(0, 0)            ← 错误！Godot 无法解析
Vector2(0.0, 0.0) ← 正确
```

---

### 🟠 14. heredoc 残留 `ENDOFFILE` 在文件中

**现象**：`Parse Error: Unexpected identifier "ENDOFFILE" in class body`

**根因**：bash heredoc 语法错误（如引号不匹配）导致 `ENDOFFILE` 字符串被写入文件末尾

**检查方法**：`grep ENDOFFILE *.gd` 查找残留

---

## 四、数据序列化

### 🔴 15. 手动 .tres 序列化遗漏属性

**现象**：`_sources` 数组保存后加载为空

**根因**：`_serialize()` 函数只写了 `_cells` 和 `_atlas`，没有写 `_sources`

**正确做法**：新增 `@export` 字段后，同步更新 `_serialize()` 函数中的序列化列表

---

### 🔴 16. 加载旧格式 .tres 文件崩溃

**现象**：`Invalid type in function: Cannot convert argument 5 from Nil to Array`

**根因**：旧格式文件没有 `_sources` 字段，`data.get()` 返回 null

**解决**：添加兼容函数：
```gdscript
func _safe_arr(arr) -> Array:
    return arr if arr is Array else []
```

---

### 🟠 17. ResourceSaver 与手动序列化的数据不一致

**现象**：测试用 `ResourceSaver.save()` 写入的文件，`_sources` 丢失

**根因**：`ResourceSaver.save()` 只保存 `@export` 变量，非导出变量不保存

**解决**：所有需要持久化的字段都添加 `@export`，或统一使用手动序列化

---

## 五、编辑器架构

### 🟠 18. 多个入口导致混乱

**现象**：房间编辑器有两个插件（独立插件 + IronEater Studio），功能重复

**根因**：逐步开发时未清理旧代码

**解决**：禁用独立插件，统一到 IronEater Studio 的标签页中

---

### 🟡 19. 编辑器功能跨场景调用失败

**现象**：插件面板的按钮无法操作 2D 视口中的 TileMapLayer

**根因**：插件通过 `get_edited_scene_root()` 访问场景节点，但场景可能未正确打开

**解决**：添加 `_root()` 的空值检查和"请先打开 room_editor.tscn"提示

## 六、开发流程教训

### 🔴 20. 每次修改后必须跑测试

**命令**：
```bash
GODOT="F:/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64.exe"
"$GODOT" --headless --path . --script res://tests/test_room.gd
"$GODOT" --headless --path . res://tests/test_dungeon.tscn
```

---

### 🟠 21. 先设计数据格式再写代码

**教训**：`_sources` 数组后期才添加，导致大量兼容性修复

**正确做法**：数据类设计时一次性确定所有字段，包括 `@export` 注解

---

### 🟠 22. 编辑器功能在面板中实现，不在场景中

**教训**：`room_editor.tscn` 的 CanvasLayer UI 和插件面板功能重复

**正确做法**：场景只放 TileMapLayer，所有编辑功能在插件面板中

---

### 🟡 23. @tool 脚本不能热重载

**现象**：修改 @tool 脚本后功能未生效

**解决**：每次修改 @tool 脚本后需重启 Godot 编辑器

## 七、当前已知限制
